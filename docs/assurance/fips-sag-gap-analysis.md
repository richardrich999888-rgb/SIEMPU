# Cryptographic module boundary and FIPS 140-3 / SAG gap analysis

**Status: no FIPS 140-3 module validation, no CAVP/ACVP algorithm validation and no SAG
evaluation is held, applied for or in progress.** This document records, area by area, what the
repository contains today and what is missing before any such evaluation could begin. Every
"missing" item is a planned task, not a claim. Milestone labels refer to the proposed, not
approved, maturation plan (`docs/hpsc/FUNDING_PLAN.md`, `docs/hpsc/HPSC_DECK.md` slide 10:
M1 TRL 5 preparation, M2 TRL 5 validation, M3 TRL 6 build, M4 TRL 6 demonstration, M5
qualification readiness).

**Revision examined:** `2b3f9ab` plus the assurance branch commits that add this document. SAG
evaluation criteria are not public; the SAG column below records only that no assessment exists
and that the sponsor must supply the route (open questions Q04 and Q15 in
`docs/requirements/open-questions.md`).

## Current cryptographic implementation, in one paragraph

All production-path cryptography is software running in the Node.js 24 runtime (OpenSSL 3.5.8 in
this container; `node assurance/kat/run.mjs` prints the version) or in the browser's WebCrypto.
The OpenSSL **default** provider is used; the OpenSSL FIPS provider is not configured and the
repository never calls `crypto.setFips` (`grep -rn "setFips" services packages apps` returns
nothing). There is therefore no defined cryptographic module in the FIPS 140-3 sense: the
cryptographic functions are spread across `packages/crypto/crypto.mjs` (endpoint),
`packages/crypto-provider/` (provider engine), `services/control/primitives.mjs` (authority),
`services/relay/auth.mjs` (relay request MAC) and `packages/transport/tls.mjs` (TLS).

## What would have to be true before an evaluation could start

1. A defined module boundary (A-01) wrapping a module that is itself validated or under
   validation; the application would then claim only to **use** that module.
2. Approved-mode operation with every non-approved function either removed or excluded from the
   boundary (A-02, A-03).
3. Self-tests and status output (A-05, A-06, A-13).
4. The sponsor's SAG evaluation route, criteria and approved algorithm list (Q04, Q15; provider
   interface Q16). None is
   available to the applicant today.

## How to re-check this document

- Algorithm KATs: `npm run kat` (`assurance/kat/run.mjs`), report `docs/assurance/kat-conformance.md`.
- Absence of FIPS mode and self-tests: `grep -rnE "setFips|getFips|self-test|selfTest" services packages apps`.
- Algorithm inventory: `grep -rnE "scryptSync|createHmac|pbkdf2|aes-256-gcm|AES-GCM|P-256" services packages apps --include=*.mjs`.
- Claims hygiene: `bash scripts/check-claims.sh` and `docs/assurance/claims-audit.md`.
